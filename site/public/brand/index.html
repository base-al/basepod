the mark

The wordmark, and the "b" cut from it

The wordmark is "basepod" in rounded, geometric, lowercase letterforms with a distinctive tucked descender on the p — a single SVG path, drawn once, reused everywhere via currentColor. It is not redrawn or restyled here. The compact mark is that same path's own b — the exact outer contour and counter subpaths that draw it in the full word, lifted out rather than a fresh drawing, then given an optically balanced crop: a plain bounding-box crop left the glyph looking bottom-heavy and pushed left (the bowl doesn't start until roughly a third of the way down, leaving empty space above-right, and its rounded edges read lighter than the stem's hard straight edges), so the frame trims tighter on the flat/empty top-left and gives the rounded bowl a little extra room bottom-right instead of padding every side by the same amount.

System-health tint

Both marks recolor via currentColor. Default presentation is brand copper; either mark can tint to a status color instead — used on the compact mark in the mobile header, where the health chip itself doesn't fit, so the mark quietly doubles as the indicator when something needs attention.

Do

  • Use the wordmark whenever there's room (rail brand slot, this page, the login screen).
  • Switch to the derived mark in the collapsed/mobile header, the favicon, and other small surfaces.
  • Recolor via currentColor — token colors only.
  • Give either mark real clear space — roughly the height of its own lowercase "a".

Don't

  • Redraw, simplify, or "clean up" the letterforms — the path is the asset.
  • Recolor outside the token set (no off-brand hues, no gradients).
  • Stretch or skew — scale uniformly only.
  • Add drop shadows, glows, bevels, or outlines.
  • Crop the derived mark to a plain bounding box again — use the optically-balanced viewBox.

palette

Copper on warm graphite

Every self-hosting tool reaches for the same neon-green-on-black. Copper is metal — hardware you own, sitting in a rack you chose — kept out of the status hue family entirely so a primary action never competes with a health signal. The neutrals carry a deliberate warm bias (not the cool blue-gray of a generic "terminal" palette) so the ground reads as considered rather than default grey.

typography

Monospace leads, prose follows

Slugs, image refs, hostnames, and numbers are things you copy, compare, and type back — they render in JetBrains Mono with tabular figures so columns line up and a stray character is visible. Headings and section labels borrow the same face, so the interface sounds like the tool it is. Running prose (descriptions, help text) stays in the platform's own system-sans stack, which is what people actually read comfortably — and needs no webfont at all. JetBrains Mono is self-hosted (SIL Open Font License 1.1, from the JetBrains Mono Project) and bundled into the app's own build, served same-origin: the dashboard's CSP (default-src 'self') blocks font CDNs outright, so anything used here has to ship in the build. Only the Latin subset of each weight is imported — the product has no i18n today.

voice

Plain, technical, honest

Say exactly what a button or an error does — not that it's "irreversible", what it deletes. Never oversell: the product is early and the docs say so plainly. These are real strings from the app, not invented copy.

UI patterns

What keeps it coherent screen to screen

Monospace, tabular, for anything a machine reads back exactly.

Slugs, image refs, hostnames, ports, tokens, deployment numbers — JetBrains Mono with tabular-nums on the digits, always. If a value could be copy-pasted into a terminal, or compared row to row, it's mono.

Status is a dot plus a word, never a dot alone.

Running/Deploying/Stopped/Error always render as a colored dot and a text label (StatusBadge). Color reinforces the word; it never replaces it.

Destructive actions require typing the name.

Deleting an app or a compose project isn't a single confirm click — the operator types the exact slug/project name before the button arms. A speed bump sized to the size of the mistake.

Secrets are shown exactly once.

A webhook secret or access token is revealed the moment it's minted (connect or rotate) and never again after that — the API doesn't return it on subsequent reads. The UI's copy says so plainly: "Copy this now — it won't be shown again."

Navigation always carries a visible text label — icon-only is never enough.

v0.4.2 shipped a bug where an icon-only Settings gear silently failed to render and made the account screen unreachable — nothing indicated a control was even there. Every nav item — the desktop rail, the mobile bottom bar — keeps real text next to its icon, permanently, as policy rather than a one-off fix.

Desktop gets a rail; phone gets a bottom bar — not one shrinking into the other.

A sidebar that just gets narrower stops being usable well before phone width. Navigation is two purpose-built layouts, not one responsive compromise.

BasePod is early and evolving — this page documents what the product is today, not where it's headed. Wordmark reused here from the project that originated it, by the same author across both.
