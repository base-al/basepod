# BasePod v0.2 Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A production-quality embedded web dashboard (Vue 3 + Nuxt UI) covering login, apps, deploy-by-image, deployments, live logs, env-var editing (encrypted at rest, injected into containers), and custom domains — plus the API/engine work those need.

**Architecture:** Frontend lives in `web/` (Vite + Vue 3 + TS + Nuxt UI), built to `web/dist`, embedded into the Go binary via `go:embed`, served by the existing API server with SPA fallback. New API surface: env CRUD (secrets write-only), domains CRUD, live logs over SSE. Engine: env injection at container create; routes gain multiple hostnames per app. Env values encrypted with a data key (`secret.key`) using XChaCha20-Poly1305.

**Tech Stack:** existing Go stack + golang.org/x/crypto/chacha20poly1305; web: Vue 3, TypeScript, Vite, @nuxt/ui (PrimeVue fallback), Pinia, vue-router, @tanstack/vue-query.

**Note:** this milestone reorders the roadmap — dashboard (was v0.3) now precedes builds/CLI (was v0.2). Task 11 amends doc 11.

## Global Constraints

- Everything from the v0.1 plan still binds: module `github.com/base-al/basepod`, labels, naming, error envelope `{"error":{"code","message"}}`, conventional commits, NO AI attribution, CGO off, `go vet` + gofmt clean, go.mod tidy.
- Node is a **build-time-only** dependency; servers still run one Go binary. Latest stable npm deps (check with `npm view <pkg> version` before adding).
- Secrets: env values encrypted at rest; secret values never returned by the API after write; never logged.
- API stays versioned under `/api/v1`; SPA served at `/` with history-mode fallback; `/api/*` always wins over static files.
- Design language (binding for all UI tasks): dense-but-calm ops dashboard; dark mode default with light toggle; neutral slate surfaces + emerald accent for healthy/primary, amber for deploying, red for errors; Nuxt UI components with a small custom theme file — no default-Bootstrap look, no walls of cards with drop shadows; monospace (ui-monospace stack) for logs, slugs, image refs, hostnames.
- A dashboard action never invents API behavior: if the API can't do it, the button doesn't exist.

Migration:

-- +goose Up
CREATE TABLE env_vars (
  id INTEGER PRIMARY KEY,

### Task 3: Engine — env injection, multi-hostname routes, ApplyRoutes

**Files:** Modify `internal/caddy/render.go` (+ golden), `internal/deploy/deploy.go`, `internal/deploy/runtime.go`; tests in both packages.

**Interface changes (breaking, coordinated here):**
```go
// caddy

// deploy

- [ ] Update render golden (one app with custom domain covers the new shape; run `caddy validate` on regenerated golden, note output in commit body). Update all AppRoute constructors/tests. ### Task 4: API — env + domains endpoints

**Files:** Create `internal/api/env.go`, `internal/api/domains.go`; Modify `internal/api/router.go` (routes + api struct gains `seal/open` funcs and `routesRefresher`); tests in `internal/api/api_test.go`.

**Contract:**
```
GET  /api/v1/apps/{slug}/env    → [{"key":"K","value":"v","is_secret":false}, {"key":"S","value":"","is_secret":true}]  (secret values always "")
PUT  /api/v1/apps/{slug}/env    body: full desired list, same shape.
     Semantics: full replace, EXCEPT an entry with is_secret=true and value=="" keeps the existing stored secret value.
     Key validation: ^[A-Z_][A-Z0-9_]{0,63}$ → 422 validation naming the key. Response: the GET shape. 
     NOTE: env changes do NOT auto-redeploy; response header X-Basepod-Redeploy-Required: true when the set changed; UI shows "redeploy to apply".
POST /api/v1/apps/{slug}/domains  {"hostname":"www.example.com"} → 201 {"hostname":...}
     Validation: lowercase FQDN regex ^([a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?\.)+[a-z]{2,}$; not equal to any <slug>.<root_domain>; 409 domain_exists on duplicate. On success: routesRefresher.ApplyRoutes(ctx) — Caddy picks it up immediately.
GET  /api/v1/apps/{slug}/domains → [{"id":1,"hostname":...}] plus "generated": "<slug>.<root>" field in a wrapper: {"generated": "...", "custom":[...]}
DELETE /api/v1/apps/{slug}/domains/{id} → 204, then ApplyRoutes.
```
`api.New` signature grows: `api.New(st, dep Deployer, ping Pinger, version string, seal func(string)(string,error), open func(string)(string,error), routes RoutesApplier)` where `RoutesApplier interface{ ApplyRoutes(context.Context) error }` (satisfied by *deploy.Engine; compile assertion). Deployer unchanged.

- [ ] TDD: env roundtrip incl. secret masking + keep-on-empty semantics; key validation; domain add/list/delete with ApplyRoutes fake recording calls; duplicate 409; generated-domain rejection. Commit `feat: env and domains API`.

### Task 5: Live logs — podman logs demux + SSE endpoint

**Interfaces:**

   // GET /containers/{id}/logs?stdout=true&stderr=true&follow=..&tail=..
podman.DemuxLogs(r io.Reader, emit func(stream string, line string)) error

```

No — add `Logs LogsDeps` param object to api.New… **keep it simple: extend the api constructor with `logs func(ctx, slug string, follow bool, tail int) (io.ReadCloser, error)` provided by a thin method on *deploy.Engine** (`Engine.AppLogs` — finds newest running container by label, calls rt; Runtime interface gains ContainerLogs). Update fakes.
