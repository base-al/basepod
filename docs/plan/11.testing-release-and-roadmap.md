# 11 — Testing, Release Engineering & Roadmap

## Testing strategy

| Layer | Tooling | What it covers |
|---|---|---|
| Unit | `go test`, `fakeRuntime`, in-memory SQLite | Business logic: RBAC matrix, config rendering (Caddy JSON, Quadlet units — golden-file tests), manifest parsing, template engine |
| API integration | `httptest` + real SQLite file | Every endpoint: auth, team scoping, error shapes; OpenAPI conformance check |
| Runtime integration | Real Podman in CI (Linux runners have it; macOS runners boot `podman machine`) | Runtime impl, build pipeline, zero-downtime swap, reconciliation |
| Edge integration | Real Caddy binary, local internal CA | Config loads, route behavior, on-demand-TLS ask flow |
| E2E | Bash/Go harness per platform | install.sh → setup → deploy sample app → HTTPS curl → rollback → uninstall |
| Frontend | Vitest + one Playwright smoke | Doc 07 |

Golden-file tests for every generated artifact (Caddy JSON, Quadlet
units, launchd plists, systemd units) are the backbone — config
generation is where PaaS bugs live.

## CI (GitHub Actions)

- **pr.yml** — lint (`golangci-lint`, `eslint`), unit + API tests
  (matrix: ubuntu-24.04 amd64/arm64), frontend build, `go vet`,
  `govulncheck`.
- **integration.yml** — Podman/Caddy/E2E suites: ubuntu-24.04,
  ubuntu-24.04-arm, macos-13 (Intel), macos-15 (ARM). The macOS legs
  boot `podman machine` — slow, so: on merge to main + nightly, not per
  PR push.
- **release.yml** — on tag: full test suite → GoReleaser.

## Release engineering

- **Versioning:** SemVer, `v0.x` until the v1.0 criteria (doc 01) hold.
  Conventional commits → generated changelog.
- **GoReleaser** builds `darwin/amd64, darwin/arm64, linux/amd64,
  linux/arm64` (CGO off everywhere — pure-Go SQLite pays off here),
  embeds version/commit via ldflags, produces tarballs + `checksums.txt`,
  publishes GitHub Release, updates `flakerimi/homebrew-tap`, and also
  `.deb`/`.rpm` via nfpm (nice-to-have, same config).
- **Artifact integrity:** SHA-256 checksums from day one; Sigstore
  cosign signing once the release flow is stable.
- **Caddy pinning:** the pinned Caddy version + checksums live in source;
  bumping Caddy = PR that runs the edge test suite.
- install.sh and `basepod upgrade` consume GitHub Releases (doc 02).

## Documentation plan

- `README.md` — pitch, 3-line install, screenshot, links.
- `docs/` site (later, e.g. VitePress): install guides per platform,
  app-deployment guide, `basepod.yaml` reference, API reference
  (from OpenAPI), plugin author guide, runbooks (backup/restore,
  migration from CapRover — including a captain-definition converter
  note), failure/troubleshooting.
- Every feature PR that changes behavior must touch docs — enforced by
  review checklist, not tooling, initially.

## Milestone roadmap

| Milestone | Contents (docs) | Exit criterion |
|---|---|---|
| **v0.1 — walking skeleton** | Repo, CI, installer, `server` boots, Podman+Caddy managed, deploy-by-image via API only (01–05) | Image → running app with HTTPS on a fresh Ubuntu VPS, API-only |
| **v0.2 — real deploys** | Tarball deploy + builds, zero-downtime, rollback, logs, CLI core (06) | `basepod deploy` from a laptop works end-to-end |
| **v0.3 — dashboard** | Dashboard v1 (07), setup wizard | A non-CLI user can do everything v0.2 does |
| **v0.4 — teams** | Users/teams/RBAC/tokens/audit (08) | Two users, two roles, matrix-tested |
| **v0.5 — git & compose** | Webhooks, compose, templates catalog (06, 09) | Push-to-deploy demo repo; Postgres template one-click |
| **v0.6 — plugins** | Event bus, webhooks-out, plugin host, 2 first-party plugins (09) | nixpacks plugin deploys a no-Containerfile repo |
| **v0.7 — multi-server** | Agent mode, servers screen, app move (10) | 2-server demo: app moved between servers, HTTPS intact |
| **v0.8–0.9 — hardening** | Backups, upgrade path tests, security pass, docs site, macOS polish | Beta users run it for 30 days without data loss |
| **v1.0** | — | Doc 01 criterion: fresh VPS/Mac → live HTTPS app in <10 min |

Sequencing rationale: every milestone ships something usable end-to-end
(walking-skeleton style), and the riskiest integrations (Podman, Caddy,
rootless networking) are validated in v0.1 before any UI or team
features stack on top.

## Risks register (top 5)

| Risk | Mitigation |
|---|---|
| Rootless networking edge cases across distros | v0.1 E2E on 3 distros; published-port fallback (doc 04) |
| `podman machine` flakiness on macOS CI | Nightly not per-PR; retry logic; treat macOS as dev-tier support |
| Nuxt UI outside Nuxt friction | Spike in v0.3 with PrimeVue fallback (doc 07) |
| Solo-maintainer scope creep | Milestones are strictly cumulative; plugin surface absorbs "wouldn't it be nice" features |
| Podman v5→v6 API drift | Runtime interface isolates bindings; version gate + CI against podman edge channel (allowed-to-fail job) |
