# 05 — Data Model & API

## Store

- SQLite via `modernc.org/sqlite` (pure Go, no CGO), WAL mode,
  `busy_timeout` set; single-writer discipline (the daemon).
- Migrations: embedded SQL files, forward-only, run on daemon start
  (tracked in `schema_migrations`). Tooling: `goose` as a library or a
  minimal in-house runner — decide at implementation, keep migrations as
  plain SQL either way.
- Backups: `basepod backup` → tar of SQLite snapshot (`VACUUM INTO`),
  Caddy data dir, env files, volume list manifest. `basepod restore`
  reverses it. Nightly timer optional.

## Schema (v1)

Multi-server readiness: resources that live on a machine carry
`server_id` from day one; phase ≤6 always uses the single seeded row
(id 1, `local`).

```sql
servers        (id, name, kind /*local|remote*/, address, agent_token_hash,
                status, last_seen_at, created_at)

users          (id, email UNIQUE, name, password_hash /*argon2id*/,
                is_superadmin, created_at, disabled_at)

teams          (id, slug UNIQUE, name, created_at)
team_members   (team_id, user_id, role /*owner|admin|member|viewer*/,
                PRIMARY KEY(team_id, user_id))

apps           (id, team_id, server_id, name, slug UNIQUE-per-team,
                source_kind /*image|tarball|git|compose*/,
                image_ref, git_url, git_branch,
                port, healthcheck_path, instances,
                cpu_limit, memory_limit,
                status /*created|deploying|running|stopped|error*/,
                created_at, updated_at)

deployments    (id, app_id, number /*per-app sequence*/, image_tag,
                trigger /*cli|ui|webhook|rollback|system*/,
                triggered_by_user_id, git_sha,
                status /*queued|building|deploying|healthy|failed|rolled_back|superseded*/,
                build_log_path, started_at, finished_at)

domains        (id, app_id, hostname UNIQUE, kind /*generated|custom*/,
                tls_status /*pending|active|error*/, tls_error,
                redirect_www, basic_auth_hash, created_at)

env_vars       (id, app_id, key, value_encrypted, is_secret,
                UNIQUE(app_id, key))

volumes        (id, app_id, name, container_path, created_at)

registries     (id, team_id, server, username, password_encrypted)

api_tokens     (id, user_id, name, token_hash, scopes, last_used_at,
                expires_at, created_at)

sessions       (id, user_id, token_hash, user_agent, ip,
                created_at, expires_at)

audit_log      (id, at, user_id, api_token_id, team_id, action,
                resource_kind, resource_id, detail_json, ip)

plugins        (id, name UNIQUE, version, source_ref, enabled,
                config_json, installed_at)

settings       (key PRIMARY KEY, value_json)   -- root_domain, acme_email, …
```

**Secrets at rest:** `env_vars.value_encrypted`, registry passwords, and
webhook secrets are encrypted with a data key stored in
`<data_dir>/secret.key` (0600, generated at setup) using
XChaCha20-Poly1305 (`golang.org/x/crypto`). Password/token columns store
hashes only (argon2id for passwords; SHA-256 for random API/agent tokens,
which have enough entropy to make brute force moot).

## API

- Base: `/api/v1`, JSON. OpenAPI 3 spec maintained in-repo
  (`api/openapi.yaml`) and served at `/api/v1/openapi.json`; dashboard
  and CLI clients are generated or hand-written against it (decide in
  implementation; spec is the contract either way).
- Auth: session cookie (dashboard; SameSite=Lax, CSRF token on mutating
  routes) or `Authorization: Bearer bp_pat_<token>` (CLI/CI).
- Errors: `{"error": {"code": "app_not_found", "message": "…"}}`;
  correct 4xx/5xx semantics; per-token rate limiting on auth endpoints.
- Team scoping: `X-Basepod-Team: <slug>` header or `?team=` — resolved
  against membership; superadmin may access all.

### Streaming

SSE for logs/build-logs/stats/events (works through Caddy and proxies,
trivial in Vue). WebSocket only where bidirectional is required
(`/exec` interactive shell).

## Auth details

- Passwords: argon2id (defaults per OWASP; parameters stored alongside
  hash for future tuning).
- Sessions: 30-day sliding expiry, revocable (listed in UI).
- PATs: `bp_pat_` prefix + 32 random bytes, shown once, hashed at rest;
  scopes v1: `read`, `deploy`, `admin` (full RBAC matrix in doc 08).
- First-run: `/setup` creates the superadmin, then locks itself.
- 2FA (TOTP): schema-ready (`users.totp_secret` added when built),
  targeted post-v1.
